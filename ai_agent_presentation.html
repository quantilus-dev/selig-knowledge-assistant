01
The one idea

What Is an AI Agent?

Beyond scripts and workflows — how modern AI agents reason, act, and scale where rule-based automation breaks down.

Scripts follow paths.
Agents choose paths.

A workflow is a decision tree drawn at design time — every branch must be anticipated. An agent is given tools and a goal, and decides at runtime which tool to call, with what arguments, in what order, and when to stop.

If nothing else from this deck sticks, this should: the decision of what to do next moves from the developer (at design time) to the agent (at runtime).

02
Definition

An agent = LLM + Tools + Loop.

LLM (the reasoner)

A large language model that reads the situation and decides what to do next. It's the brain — the part that handles messy input and composes multi-step plans.

Tools (the action surface)

Functions the model can call: query a database, send an email, page a human, create a CRM lead. Each tool is a well-defined capability the agent can choose to invoke.

Loop (the runtime)

Plan → call a tool → read the result → decide whether to stop, call another tool, or ask the user → repeat. The loop is what people miss — a chatbot that answers once is not an agent.

Simple test: if your automation does one LLM call and stops, it's a chatbot. If it calls tools, reads results, and chooses its next step, it's an agent.

04
Where scripts break

Scripts vs. agents — the same Selig queries.

Customer messageScripted workflowAI agent
"Hot-fill acidic sauce, pH 3.8, HDPE 38mm, food-grade, recyclable preferred." Needs intent classifier + entity extractors for pH / container / closure / regulatory / sustainability, then a rules engine. Adding "alkaline" later = new branch. Reads the sentence, retrieves datasheets, reasons about acid resistance + HDPE bonding, excludes PVDC for recyclability. One turn, with justification.
"we hav a issue wif the oenoseel on our pinot, few bottles leking" Keyword match fails. "oenoseel" and "leking" aren't in the vocabulary. Routes to generic FAQ or "I don't understand." Just works. Reads intent (quality complaint, OenoSeal line, wine application, post-install timeframe) and triages.
"Email me the EPE 30 spec AND 500 samples by Tuesday AND what's MOQ?" Assumes one intent per turn. Drops two of the three, or forces user through three forms. Decomposes into parallel tool calls: send_spec, request_sample, lookup_moq.
Turn 2: "Switch that to the second one, add a spec sheet." Brittle slot-filling. "The second one" resolves to nothing. Re-prompts the user. Holds prior turn in context. "The second one" = Safe-Gard Plus SG-735. Done.
"Recyclable food-grade — but NOT PVDC or aluminum foil." Negation is a classic failure mode. Keyword search returns PVDC options anyway. Handles the constraint natively.
05
How it's built

Anatomy of the Selig agent.

LAYER 1

Model

Gemini / Claude / GPT. Swappable in one config line. Tune cost vs. quality.

LAYER 2

Prompt

Role, policies, steering. "Never quote prices." "Correct MVTR/GTR units." One sentence = one policy.

LAYER 3

Knowledge

Curated wiki (15 files) + TF-IDF retrieval over 110 datasheets. Agent decides what to pull per turn.

LAYER 4

Tools

Functions the agent can call — CRM, ERP, email, Slack, quote generator. Each ~30 lines of code.

LAYER 5

Skills / sub-agents

Specialist agents: QuoteBuilder, RegulatoryCheck, ComplaintTriage. Compose like functions.

LAYER 6

Memory

Session (this chat) + per-customer (Acme uses SG-733) + org-level (common questions).

LAYER 7

Loop / runtime

The plan → act → observe → decide cycle. Without this, it's just a chatbot.

LAYER 8

Guardrails

Permissions, approval gates, audit logs, evals. Production requires this.

Today's Selig chatbot has layers 1–3. Layers 4–8 are the growth path.

06
Layer 2 deep dive

Prompt as policy — a live example.

Selig's original datasheets have a unit typo: MVTR and GTR Oxygen values are swapped in the PDFs.

Script world

  • Regex every extracted MVTR value
  • Regex every extracted GTR value
  • Unit-conversion module
  • Test case per product family
  • Fragile — breaks on new PDF formats

Agent world

"MVTR must be expressed as gm/100 sq.in./24hrs (it is a mass value). GTR Oxygen must be expressed as cc/100 sq.in./24hrs (it is a volume value). Silently correct and note 'units corrected from source document'."

— Four lines in selig_app.py. Zero regex. Works on every product family, including new ones.

Other policies added the same way: "Never quote prices," "Flag pharma for compliance," "Pivot tactfully on competitor mentions," "Always close with a next step." Each is one sentence. In a script, each is a module.

07
Layer 4 deep dive

Tools — the agent's action surface.

Each tool is a named function with typed arguments. The agent picks which to call based on the conversation.

Information tools (read)

  • lookup_datasheet(product)
  • check_inventory(sku, qty)
  • lookup_customer(email)
  • get_order_status(po)
  • chemical_compatibility(substance, product)
  • regulatory_check(product, market)
  • lookup_competitor_equivalent(product)

Action tools (write)

  • send_spec_email(product, recipient)
  • request_sample(product, qty, addr, deadline)
  • generate_quote_draft(...)
  • create_crm_lead(...)
  • open_qa_ticket(lot, symptom, severity)
  • escalate_to_slack(team, priority, context)
  • schedule_meeting(rep, customer, topic)

Adding capability: in an agent, you add a tool to the registry. In a script, you add intents, routes, branches, and regression tests for every existing flow.

09
Level 1 · Knowledge

Level 1 — answer what we know.

Where we are today. Pure retrieval + reasoning, no tools.

Real scenarios

  • "What's the MVTR of ALPHASEAL Woodpulp PET 1.60mm?" → pulls value, applies unit correction silently.
  • "Difference between Lift 'n' Peel LPF, LPT, and LPTZD?" → comparison from wiki.
  • "PVDC-free options for pharma with good moisture barrier?" → reasons across wiki, excludes PVDC SKUs, recommends foil-faced alternatives.
  • "Which liners are EU food-contact compliant?" → aggregated answer across product families.

Why this is already non-trivial: each question mixes fuzzy language, negation, and multi-family reasoning. A keyword-based FAQ would miss half of them. This is the floor of what "AI" buys you — the ceiling is four more rungs up.

10
Level 2 · Qualify

Level 2 — detect intent, qualify leads.

The agent watches for signals and silently feeds the CRM.

Real scenarios

  • Tier-1 detection. Visitor from @ab-inbev.com → flags enterprise, routes to enterprise AE at session end.
  • BANT qualification. "5M units/year, launching Q3, currently with a domestic supplier" → fills budget/timing/need, scores lead automatically.
  • Student filter. "I'm writing a thesis" → tagged educational, answers generously, doesn't flood the CRM.
  • Evaluation mode. Same visitor asks about Lift 'n' Peel, then Uni-Gard, then DeltaSeal → recognizes comparison-shopping, alerts AE: "likely competitive situation."
  • Stuck-deal detection. Same technical question from the same email twice in 3 weeks → flags "stalled opportunity, no rep follow-up."

What scripts choke on: reading between the lines of free-form chat. Rules-based triggers are either too loose (everyone's Tier-1) or too tight (everyone's a student).

11
Level 3 · Transact

Level 3 — do work on the customer's behalf.

Real scenarios

  • One-shot sample request. "200 samples of Uni-Foam EPE 30 to our Dallas plant" → validates SKU, pulls shipping address from CRM, checks deadline feasibility, submits, returns tracking.
  • Quote draft. "Rough quote for 500K Top Tab 2 TT2-518, annual" → drafts quote, emails rep for approval, replies to customer: "Jane will send a firm quote today." Human-in-the-loop by design.
  • Compliance letter on demand. "I need a 21 CFR 175 letter for Uni-Foam EPE 42_S" → fills template, generates PDF, emails signed copy.
  • Chemical compatibility. "Is CORELEN PE 2020 compatible with d-limonene?" → queries chem DB, warns on terpene sensitivity, suggests TRESYLENE 4015 PET, offers samples of both.
  • Regulatory scoping. "Launching in Brazil — which of my SKUs stay compliant?" → cross-references ANVISA, flags gaps, suggests replacements.
12
Level 4 · Escalate

Level 4 — sentiment & human handoff.

Real scenarios

  • Quality incident. "URGENT — 40% pinholes on lot 8842, line stopped, losing $30K/hour" → pages QA on-call via Slack in 5 seconds, pre-fills ticket with lot/line/product, sends first-response acknowledgement to customer.
  • Frustration. "This is the third time I've asked" → escalates with apology, pulls prior conversations, tags CSAT risk.
  • Retention risk. "We're evaluating switching suppliers" → responds respectfully, gathers reasons, notifies account manager — without pushing back.
  • Structured complaint intake. Seal failure? → walks customer through lot, fill temp, pH, closure type, failure timeline; opens QA ticket with all fields populated.
  • Language handoff. French-Canadian customer with a regulatory question → answers in French, routes to Bradford, ON rep.

What scripts choke on: the difference between "I'm frustrated but engaged" and "about to switch suppliers" is 10 points of response priority. Rules-based sentiment is notoriously bad at this nuance.

13
Level 5 · Proactive

Level 5 — agents working while nobody's watching.

No customer on the other end. The agent does work on a schedule.

Real scenarios

  • Nightly sample follow-up. Scans samples unacknowledged for 14 days, drafts personalized follow-ups citing the specific product sampled. Queues for AE approval.
  • Weekly wiki gap analysis. "7 customers asked about Circumvent™ venting, no wiki page exists" → drafts a new page, flags for review.
  • Monthly regulatory watch. Scans FDA / EU / ANVISA updates, flags Selig products affected, drafts advisories.
  • Quarterly churn-risk report. Combines CRM notes + chat sentiment history + order volume → ranked list with "probable reason" per account.
  • Live inventory reconciliation. "This $2M quote for TRESYLENE 2520 will shortfall production if it closes this week" — pings production and AE simultaneously.

What scripts choke on: everything here requires drafting and judgment, not rule-matching. Scripts can schedule reports. They can't draft a customer-specific follow-up email.

14
Why it matters

Six reasons agents are powerful — concretely.

1. Unstructured input is free

Typos, synonyms, mixed languages, copy-pasted email noise. "alfaseel 1.6" resolves to ALPHASEAL 1.60mm. No new preprocessing module.

2. New capability = add a tool

Week 1 answers questions. Week 2 adds check_inventory. Week 3 adds request_sample. No rebuild, no regression.

3. NL is the UI for every system

"How many OenoSeal samples shipped to Napa last quarter?" — one agent, every backend. No new dashboard.

4. Graceful degradation

ERP down? Agent says "I'll check stock in an hour." Missing spec field? "Routing to tech team." Scripts die at the first unexpected state.

5. Compositional planning

Five sub-tasks invented at runtime — filter, compare, generate PDF, email, log. Scripts require that sequence to be anticipated.

6. Policy in prose

"Never quote prices; flag pharma; pivot on competitor mentions" — three sentences vs. three middleware modules.

17
Be honest

Caveats — where agents shouldn't go.

Real limitations

  • Non-deterministic. Not for safety-critical control loops. Keep scripts for verified operations.
  • Latency & cost per turn are higher than a hardcoded API call. Matters at volume.
  • Needs guardrails: tool permissions, approval gates, audit logs, evals.
  • Hallucinations happen. Ground in real data; test continuously.
  • Change management. "The bot did something weird" is a new failure mode for support teams.

The mature answer

Agent + scripts, not agent vs. scripts.

  • The agent orchestrates — reads messy input, picks the right action.
  • Scripts execute — deterministic, tested, verified operations.
  • Humans approve — at the boundaries that matter (quotes, escalations, compliance).

The agent is the reasoning layer. Everything below it can stay exactly as reliable as it is today.
